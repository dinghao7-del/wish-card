# 星愿卡小天才手表客户端设计与发布要素

> 日期：2026-05-17
> 适用项目：`forest-family / 星愿卡`
> 目标：为小天才电话手表端新增一个轻量孩子端客户端，完成从产品范围、界面设计、技术适配到发布提审材料的准备清单。

## 1. 结论先行

小天才手表端不应复刻完整 Web / 小程序 / Android / iOS 客户端。它应作为“孩子当天行动入口”，只承载高频、低输入、低风险动作：

- 看今天要做什么。
- 一键提交完成。
- 查看星星余额。
- 查看当前愿望进度。
- 向家长发出求助或稍后提醒。

家长侧的创建计划、审核、奖励配置、家庭建档、AI 长对话、报表和商业推荐，继续留在手机端、小程序端或 Web 端。

## 2. 当前项目可复用基础

### 2.1 可复用业务模型

项目已有核心模型可以直接成为表端数据源：

- 成员角色：`parent` / `child`。
- 任务状态：`pending`、`in_progress`、`reviewing`、`completed`、`expired`。
- 任务生命周期：孩子完成后进入 `reviewing`，家长审核后进入 `completed`，再发放星星。
- 星星经济：完成任务获得星星，星星用于兑换奖励。
- 同步模型：本地写入、远端同步、多端刷新。

### 2.2 可复用设计资产

- 主色：森林绿体系，但表端应减少浅色背景使用。
- 图标：任务、星星、愿望、提醒等可以沿用现有图标语义。
- 插画：欢迎页绿色家庭漫画可作为应用商店介绍图素材，但表端 UI 内不宜大量使用大图。
- 文案语气：温和、鼓励、亲子协作，而不是打卡压力或控制感。

### 2.3 不建议直接复用的内容

- 完整 React WebView 壳：对手表性能、内存、包体不友好。
- Framer Motion 复杂动效：功耗和性能风险高。
- 大图背景、毛玻璃、复杂卡片层级：表端可读性和触控不稳定。
- 多语言、商业资源、AI 分析页：不属于首版表端高频闭环。

## 3. 产品范围

### 3.1 首版必须有

| 模块 | 表端功能 | 对应主端能力 |
| --- | --- | --- |
| 今日任务 | 展示当天 3-5 个任务 | `Tasks` / `Home` |
| 任务详情 | 标题、时间、奖励星星、简短说明 | `Task` 模型 |
| 完成提交 | 一键“完成了”并进入待审核 | `completeTask()` / `reviewing` |
| 稍后提醒 | 选择 10/30/60 分钟后提醒 | 本地通知 / 任务提醒 |
| 求助家长 | 发送“我需要帮忙”状态 | 通知中心 |
| 星星余额 | 当前星星数、今日新增 | `Member.stars` / history |
| 愿望进度 | 一个当前目标奖励，显示还差多少星 | `Reward` |
| 离线队列 | 无网时保存完成/稍后/求助动作 | 同步引擎 |

### 3.2 首版不做

- 不在手表上创建任务。
- 不在手表上编辑计划。
- 不在手表上兑换高价值奖励。
- 不在手表上做家长审核。
- 不在手表上展示完整家庭成员列表。
- 不接入广告、外链、商业推荐。
- 不做开放式 AI 聊天。

### 3.3 第二阶段可考虑

- 语音播报今日任务。
- 基于表端运动能力做跳绳、户外、运动类任务的自动辅助记录。
- 小天才家长 APP 服务号：让家长从小天才家长 APP 看到使用数据、功能管理或服务入口。
- 任务完成后轻量语音鼓励。

## 4. 信息架构

### 4.1 表端主导航

建议只保留 3 个一级页：

1. `今日`
   - 当前任务卡。
   - 左右滑切任务。
   - 主按钮：`完成了`。
   - 次按钮：`稍后`、`求助`。

2. `星星`
   - 当前星星数。
   - 今天获得。
   - 最近 3 条变化。

3. `愿望`
   - 当前愿望。
   - 需要星星数。
   - 还差多少。
   - 家长承诺提示。

### 4.2 任务卡信息层级

单张任务卡最多显示：

- 任务名：不超过 12 个中文字符。
- 时间：如 `18:30` / `今天睡前`。
- 奖励：如 `+3 星`。
- 状态：待完成、待审核、已完成。
- 简短说明：最多 1 行。

超过 1 行的复杂描述应在家长端管理，表端只显示行动指令。

## 5. 表端设计规范

### 5.1 基础尺寸

小天才官方视觉文档以 `320 x 360 px` 作为表端设计基准。项目应新增 `watch` 设计断点或独立 token：

| Token | 建议值 |
| --- | --- |
| `watch-width` | `320px` |
| `watch-height` | `360px` |
| `watch-safe-x` | `18px` |
| `watch-safe-y` | `16px` |
| `watch-radius-card` | `16px` |
| `watch-radius-button` | `999px` |
| `watch-touch-min` | `56px` |

### 5.2 颜色

小天才官方建议表端界面采用黑色背景。星愿卡手表版应从现有绿色家庭视觉收敛成“深色底 + 绿色行动色 + 黄色星星反馈”：

| 用途 | 建议 |
| --- | --- |
| 背景 | `#050805` / 接近黑色 |
| 主按钮 | 沿用森林绿，但提高亮度 |
| 星星 | 暖黄色 |
| 文字 | 白色 / 高对比灰白 |
| 警示 | 只用于异常，不用于日常压力提示 |

### 5.3 字号

| 层级 | 建议字号 |
| --- | --- |
| 大数字 | `40-52px` |
| 页面标题 | `24-28px` |
| 任务标题 | `22-26px` |
| 正文 | `17-20px` |
| 辅助说明 | `14-16px` |
| 按钮文字 | `18-22px` |

原则：不要把手机端 14px/16px 文案直接搬到手表端。

### 5.4 触控

- 主要按钮高度不低于 `56px`。
- 底部和四角不要放关键操作，小天才文档提醒部分型号边缘/角落触控不稳定。
- 一屏最多一个主操作。
- 使用大面积可点区域，不依赖小图标精确点击。
- 避免复杂长按、拖拽、多指手势。

### 5.5 动效

允许：

- 完成任务后的 0.6-1 秒星星反馈。
- 数字轻微跳动。
- 短震动。

不建议：

- 全屏粒子雨。
- 大量循环动画。
- 长时间发光或呼吸。
- 动态背景。

## 6. 技术适配要素

### 6.1 推荐工程形态

建议新增独立客户端目录：

```text
watch/
  app/
  src/
    screens/
    components/
    data/
    sync/
  assets/
  docs/
```

如后续确认小天才支持的具体运行形态，再决定是：

- 原生 Android 轻量客户端。
- 小天才 JS / 快应用框架。
- 与现有 Android 工程共享一部分 Kotlin/Java 基础能力。

首版不建议以完整 Capacitor WebView 作为正式提审包。

### 6.2 性能红线

小天才官方注意事项中明确：

- 内存不得超过 `35M`，单个应用最大可用内存 `48M`。
- CPU 使用超过 90% 的时间段不得超过总体的 10%。
- 4G 及以上 ROM 机型：安装包不超过 `30M`，安装后不超过 `40M`。
- 512M ROM 机型：安装包不超过 `10M`，安装后不超过 `15M`。
- 不允许热更新，所有新特性需经过小天才应用商店审核。

因此首版要控制：

- 不打包大字体。
- 不打包多套大插画。
- 不引入重型动画库。
- 不常驻后台长连接。
- 不做高频轮询。
- 不在后台保活。

### 6.3 数据同步

表端写操作应只有低风险事件：

| 动作 | 本地记录 | 远端效果 |
| --- | --- | --- |
| 完成任务 | `complete_task_queued` | 任务进入待审核 |
| 稍后提醒 | `snooze_task_local` | 本地通知即可 |
| 求助家长 | `ask_parent_help_queued` | 家长端通知 |
| 查看愿望 | 无需写入 | 可选埋点 |

同步规则：

- 无网时先入本地队列。
- 来网后批量同步，避免频繁唤醒网络。
- 同一任务重复点击完成，只保留一次有效提交。
- 家长已审核或任务已过期时，表端显示最新状态，不覆盖主端状态。

### 6.4 登录与绑定

建议采用“家长端生成绑定码 / 二维码，手表端确认绑定”的模式：

1. 家长在手机端选择孩子。
2. 生成一次性绑定码。
3. 手表输入短码或扫码绑定。
4. 手表只获得该孩子的最小权限。

不建议让孩子在表端输入邮箱、手机号、复杂密码。

### 6.5 隐私与儿童保护

表端不得展示：

- 家庭住址。
- 学校、班级、详细行程。
- 家长手机号。
- 医疗、诊断、敏感备注。
- 商业推荐标签。

表端本地存储只保留：

- 孩子昵称或头像代号。
- 今日任务摘要。
- 当前星星余额。
- 当前愿望摘要。
- 待同步轻量事件。

## 7. 发布材料清单

### 7.1 小天才应用基础信息

| 材料 | 要求 |
| --- | --- |
| 应用名 | 建议 `星愿卡` 或 `星愿卡手表助手` |
| APK 包 | 包体满足小天才限制 |
| 图标 | `148 x 148 px`，PNG，直角方形 |
| 应用介绍图 | `320 x 360 px`，PNG，3-5 张 |
| 应用简介 | 20 字以内 |
| 应用详情 | 100 字以内，必须与功能一致 |
| 用户协议 | HTTPS 链接 |
| 隐私政策 | HTTPS 链接 |
| 应用软著 | 按平台要求提供 |
| 更新说明 | 面向用户版本说明 + 测试改动清单 |
| 开发者信息 | 企业名称、营业执照等 |
| 联系方式 | 客服邮箱、服务号或热线 |
| 使用说明 | 提供给小天才客服辅助答疑 |

### 7.2 推荐文案

应用简介（20 字以内）：

> 孩子的任务与星星助手

应用详情（100 字以内）：

> 星愿卡手表助手帮助孩子查看今日任务、提交完成、获得星星，并查看愿望进度。任务与奖励由家长在手机端管理，孩子端只保留轻量操作，适合家庭日常习惯养成与亲子约定。

版本更新说明：

> 首版支持今日任务查看、任务完成提交、星星余额、愿望进度和离线同步。

### 7.3 测试报告必测用例

| 场景 | 结果要求 |
| --- | --- |
| 首次打开 | 能进入绑定/登录流程 |
| 家长绑定孩子 | 手表只显示对应孩子数据 |
| 今日无任务 | 显示友好空状态 |
| 今日有任务 | 任务内容正确，按钮可点击 |
| 点击完成 | 任务进入待审核，不重复提交 |
| 家长审核通过 | 手表星星余额刷新 |
| 离线完成任务 | 本地保存，联网后同步 |
| 流量禁用 | 显示离线状态，不频繁重试 |
| 任务过期 | 不允许错误提交 |
| 多机型 | 320x360 核心布局不遮挡 |
| 内存 | 不超过官方红线 |
| 包体 | 满足 30M/10M 对应机型限制 |
| 卸载 | 本地应用数据可清理 |

### 7.4 提交方式

根据小天才“版本提供”文档：

- 新应用上架：应用基础信息、测试报告等打包发送至 `developer@eebbk.com`。
- 迭代版本：详细改动说明、测试报告打包发送至同一邮箱。
- 邮件标题格式：`〖版本验收〗xx应用`。
- 每次 APK `versionCode` 必须在上次基础上 +1。
- 每次 APK `packageName` 不能变动。

## 8. 首版里程碑

### M0：确认接入形态

- 确认使用原生 Android、快应用框架或小天才 JS 框架。
- 确认目标开放机型和最低系统版本。
- 确认是否接入小天才账号授权和应用服务号。

### M1：设计稿与信息架构

- 输出 320x360 表端主流程图。
- 输出 `今日 / 星星 / 愿望` 三个主页面。
- 输出空状态、离线状态、待审核状态、完成状态。
- 输出应用介绍图 3-5 张。

### M2：最小可用客户端

- 绑定孩子身份。
- 拉取今日任务。
- 提交完成。
- 展示星星余额和愿望进度。
- 本地离线队列。

### M3：提测准备

- 内存、CPU、包体自测。
- 多机型截图。
- 测试报告。
- 隐私政策、用户协议、软著、免责函。
- 邮件提测包。

## 9. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 直接复用 WebView 太重 | 内存/包体/性能不过审 | 独立轻量客户端 |
| 权限申请过多 | 审核风险 | 只申请网络、通知/震动等必要权限 |
| 孩子端输入复杂 | 体验差 | 家长端绑定，表端短码确认 |
| 表端展示隐私数据 | 儿童隐私风险 | 只展示任务摘要和星星 |
| 后台长连接 | 功耗不过审 | 批量同步，避免保活 |
| 热更新思路沿用移动端 | 平台不允许 | 所有新特性走版本审核 |
| 多型号差异 | UI 或能力不一致 | 读取机型并做能力降级 |
