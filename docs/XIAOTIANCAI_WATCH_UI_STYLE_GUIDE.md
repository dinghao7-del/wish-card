# 星愿卡小天才手表端 UI 推荐视觉规范

> 日期：2026-05-17
> 目标：在多风格探索后，收敛出可用于后续实现、设计评审和提审截图的一套手表端视觉基线。

## 1. 推荐方向

采用“森林星愿 + 运动能量 + 家长可信 + 户外探险”的混合方案：

- 基础视觉：`森林星愿`，延续星愿卡绿色家庭品牌。
- 运动过程：吸收 `运动能量` 的高对比数字、进度环和蓝绿能量色。
- 审核与权限：吸收 `家长可信` 的克制信息结构。
- 户外任务：吸收 `户外探险` 的暖色地点提示和挑战感。

不建议把 `童趣星糖` 作为主视觉。它适合低龄儿童活动页或空状态，但作为系统主界面会削弱可信感。

## 2. 设计原则

1. 一屏一个主意图：孩子打开手表后只需要知道下一步。
2. 传感器只做辅助证明：不把手表做成监控工具。
3. 大数字优先：运动、星星、愿望进度都以大数字承载成就感。
4. 黑底优先：符合小屏、省电、高对比需求。
5. 权限可降级：不开相机、定位、传感器也能完成基础任务。
6. 家长最终确认：星星发放和争议判断仍在家长端完成。

## 5. 控件规范

### 5.1 主按钮

- 高度：`50-56px`。
- 圆角：`999px`。
- 用途：完成、继续、我到了、拍一下、手动提交。
- 一屏最多一个强主按钮；必要时加一个弱次按钮。

### 5.2 内容卡

- 圆角：`18-20px`。
- 背景：深绿黑 `#121b11`。
- 边框：低透明白色。
- 卡内最多放：状态、主数字、短说明、进度条。

### 5.3 状态胶囊

- 用途：`+3 星`、`稳定`、`需照片`、`还差 22`、`保护隐私`。
- 文案短，最多 4 个中文字符或 1 个数字 + 单位。

### 5.4 Tab

- 仅用于三个一级入口：`今日`、`星星`、`愿望`。
- 高度不超过 `36px`。
- 选中态用绿色填充。

## 6. 页面组合

首版建议准备 8 个关键页面：

1. `今日任务`：基础入口。
2. `计步任务`：运动自动统计。
3. `跳绳计数`：传感器估算。
4. `拍照证明`：成果证据。
5. `地点提醒`：户外任务。
6. `愿望进度`：奖励目标。
7. `待家长确认`：审核关系。
8. `权限降级`：合规兜底。

这 8 页既能指导开发，也能作为小天才提审截图素材的第一版基础。

## 7. 禁止项

- 不做实时轨迹页。
- 不做长排行榜。
- 不做复杂家庭管理。
- 不在孩子端展示商业推荐。
- 不要求拍摄人脸或家庭/学校敏感环境。
- 不把运动估算写成确定事实，例如“跳绳 96 次”应写成“估计 96 次”。
- 不因拒绝权限而阻断基础任务闭环。
