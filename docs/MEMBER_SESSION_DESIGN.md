# 家庭成员会话设计

## 当前目标

一个登录账号代表一个家庭。家庭内的爸爸、妈妈、孩子不再各自注册互联网账号，而是在家庭账号下通过 PIN 或独立密码切换成员身份。

这一版先建立本地成员会话，保证离线状态下也能知道“当前是谁在操作”，并为后续在线同步、权限审计和冲突处理留下稳定入口。

## 会话模型

- `familyId`: 当前家庭。
- `memberId`: 当前家庭成员。
- `role`: `parent` 或 `child`，用于本地权限体验。
- `verificationMethod`: 本次切换通过 `pin`、`password`、`none` 或主账号 `account` 进入。
- `issuedAt` / `expiresAt`: 本地会话有效期。当前默认 12 小时。

## 边界说明

本地成员会话不是强安全认证。它解决的是家庭设备内的身份切换、离线操作归属和用户体验问题。

真正的云端安全仍然需要服务端规则兜底：

- 数据必须按主账号所属家庭隔离。
- 家长级操作需要服务端 RPC 或 RLS 校验。
- PIN 和成员密码后续应改为哈希保存，不能长期明文存储。
- 同步上传时应把 `actorMemberId` 作为操作归属，而不是把它当作互联网登录身份。

## 后续推进

1. 设计云端家庭主账号表，把 `auth.uid()` 与 `familyId` 绑定，再用成员会话作为家庭内部身份。
2. 将 `actorMemberId` 升级为服务端审计字段或 RPC 参数，用于云端安全校验。
3. 把二次确认升级为短时有效的服务端成员会话 token，而不是只做本地确认。

## 已落地

- 本地成员会话会保存到 `ff_member_session`。
- `DataLayer` 在每次写入离线同步队列时，会把当前家庭成员写入 `actorMemberId`。
- `SyncEngine` 保留 `actorMemberId` 作为队列元数据，但上传表数据前会过滤它，避免当前数据库还没有审计字段时写入失败。
- 删除成员、修改成员 PIN/密码、高价值心愿确认已接入家长二次确认。当前规则优先要求输入家长 PIN，没有 PIN 时使用家长密码。
