# 星愿卡小天才手表传感器延展方案

> 日期：2026-05-17
> 目标：把小天才手表的步数、运动传感、相机、定位、通知等能力，转化为星愿卡的深度产品能力，而不是简单做“手表打卡”。

## 1. 能力边界结论

| 能力 | 官方/平台状态 | 星愿卡建议 |
| --- | --- | --- |
| 步数 | 小天才开放平台有步数获取接口，需要 `com.xtc.motion.permission.READ_MOTION_STATE` | 首版优先接入，用于户外走路、运动量、日常活跃任务 |
| 相机/相册 | 小天才开放平台提供通用拍照/相册文档 | 二期接入，用于低频证据型任务，必须家长授权 |
| 通知 | 官方有通知栏适配 | 首版可接入，用于任务提醒、待审核反馈、家长确认结果 |
| 定位 | 官方 API 文档仍列为“待支持功能” | 暂不作为首版依赖；先做能力预留和家长端策略 |
| 陀螺仪/加速度计 | 小天才 API 文档未列专门接口，理论上可按 Android 传感器验证 | 先做实验能力，用于跳绳/运动姿态估算，必须真机验证 |
| 翻盖状态 | Z6 系列支持监听翻盖状态 | 可做“打开手表自动继续任务”的体验增强 |
| 分享/服务号 | 官方支持分享和家长 APP 服务号 | 可用于家长报告、亲子互动、任务成果传播 |

原则：能通过传感器自动验收的任务，减少孩子手动点“完成”；不能稳定自动验收的任务，只做“辅助证据”，最终仍由家长确认。

## 2. 核心产品方向

### 2.1 从“主观打卡”升级到“可信完成记录”

现在的任务完成主要靠孩子点击。手表版可以把完成记录拆成三层：

1. `孩子提交`：孩子说完成了。
2. `手表辅助证明`：步数、运动时长、照片、位置范围等轻证据。
3. `家长确认`：家长端最终审核并发星星。

这样不会把手表变成监控工具，也能让家长更信任孩子的努力。

### 2.2 从“任务 App”升级到“家庭成长感知器”

手表天然贴着孩子，最适合采集轻量、即时、低打扰的数据：

- 今天有没有动起来。
- 任务是否在合适地点完成。
- 是否按时开始和结束。
- 是否需要家长帮忙。
- 哪些任务孩子总是拖延或跳过。

这些数据不应该直接惩罚孩子，而应该进入家庭复盘和计划调整。

## 3. 传感器功能设计

### 3.1 运动任务自动统计

适合任务：

- 每天走路 3000 步。
- 放学后户外 20 分钟。
- 周末公园活动。
- 运动会准备。
- 体能习惯养成。

表端体验：

- 任务卡显示目标：`还差 800 步` / `已完成 12 分钟`。
- 开始后显示大数字进度。
- 达标后自动进入 `待家长确认`。
- 未达标也允许孩子提交“我做了，但手表没记全”，交给家长判断。

数据记录：

```text
watch_activity_session
  taskId
  memberId
  metricType: steps | active_minutes | jump_rope_estimate
  targetValue
  currentValue
  startedAt
  endedAt
  confidence: high | medium | low
  source: xtc_steps | android_sensor | manual_fallback
```

产品规则：

- 步数达标只证明“运动量”，不证明具体运动项目。
- 跳绳、跑步等细分项目只能做估算，不能作为强审核依据。
- 家长端展示“手表记录：约 1420 步 / 18 分钟”，避免给出过度精确结论。

### 3.2 跳绳/摆臂类动作识别

可用能力：

- 加速度计、陀螺仪或 Android 传感器。
- 周期性手腕摆动特征。

适合任务：

- 跳绳 100 个。
- 原地开合跳 30 个。
- 拍球 50 次。
- 运动热身 5 分钟。

表端体验：

- 开始前提示：`戴紧一点，按开始后再跳`。
- 过程显示：`估计 68 / 100`。
- 低置信度时显示：`记录不稳定，可以手动提交给家长确认`。

算法原则：

- 只做轻量本地识别，不上传原始传感器流。
- 只保存汇总值、时间段和置信度。
- 不把估算次数作为惩罚依据。

风险：

- 不同佩戴方式、左右手、松紧程度都会影响准确率。
- 手表机型传感器能力不同，需要做机型白名单。

### 3.3 拍照证据打卡

适合任务：

- 整理书桌。
- 完成手工作品。
- 阅读书页。
- 画画练习。
- 家务成果。

表端体验：

- 任务详情出现 `拍一下`。
- 拍照后只在表端显示缩略图和 `提交给家长`。
- 家长端看到照片后审核。

隐私规则：

- 只在家长明确配置“需要照片证明”的任务中启用。
- 默认不要求拍照。
- 禁止要求拍摄人脸、学校、家庭住址、身份证件、聊天记录等敏感内容。
- 可在本地压缩到低分辨率，只用于审核，不做公开分享。

推荐文案：

> 拍一张成果就好，不需要拍到人。

### 3.4 定位与地点型任务

定位能力在小天才官方 API 文档中仍列为待支持，所以设计上要分两档：

第一档，当前可先做的弱地点能力：

- 家长端创建“地点标签”：家、学校、公园、培训机构。
- 表端不主动持续定位，只展示任务地点提示。
- 孩子到任务地点后手动点 `我到了`。

第二档，平台能力确认后启用：

- 到达公园后自动提示户外任务。
- 离开学校后提示回家路上的任务。
- 到家后提醒整理书包。
- 在家长端显示“任务大概在家庭设定地点附近完成”。

隐私边界：

- 不做实时轨迹。
- 不做历史路线回放。
- 不给孩子端显示精确地图。
- 不把位置用于广告或商业推荐。
- 只保存“地点标签命中/未命中”，不保存精确经纬度，除非家长单独授权。

### 3.5 相机 + 运动 + 位置的组合玩法

| 场景 | 组合能力 | 产品价值 |
| --- | --- | --- |
| 公园户外挑战 | 步数 + 地点标签 + 结束照片 | 证明孩子真的去户外活动了 |
| 家务小队 | 照片前后对比 + 家长审核 | 让成果可见，不只靠口头描述 |
| 阅读打卡 | 计时 + 书页照片 | 低成本证明阅读过程 |
| 运动习惯 | 步数/动作估算 + 连续天数 | 形成长期习惯趋势 |
| 亲子兑现 | 愿望进度 + 地点/照片回忆 | 让奖励兑现变成家庭记忆 |

## 4. 新增任务类型

### 4.1 计步任务

```text
type: watch_steps
target: 3000
unit: steps
completion: currentSteps >= target
approval: parent_optional
```

### 4.2 运动时长任务

```text
type: watch_active_minutes
target: 20
unit: minutes
completion: activeMinutes >= target
approval: parent_required
```

### 4.3 动作估算任务

```text
type: watch_motion_count
motionKind: jump_rope | jumping_jack | ball_bounce
target: 100
unit: count
completion: estimatedCount >= target && confidence != low
approval: parent_required
```

### 4.4 拍照证明任务

```text
type: watch_photo_proof
proofRequired: true
proofHint: "拍桌面，不用拍人"
approval: parent_required
```

### 4.5 地点提醒任务

```text
type: watch_place_hint
placeTag: home | school | park | custom
completion: manual_submit
approval: parent_required
locationMode: off | approximate | tag_only
```

## 5. UI 延展

### 5.1 运动进行中

屏幕重点：

- 大数字：`1280`
- 目标：`/ 2000 步`
- 状态：`还差 720 步`
- 主按钮：`暂停`
- 次按钮：`结束`

### 5.2 动作计数

屏幕重点：

- 大数字：`68`
- 目标：`/ 100`
- 置信度：`记录稳定`
- 提示：`手表戴紧一点`

### 5.3 拍照证明

屏幕重点：

- 任务名。
- 拍照提示。
- 主按钮：`拍一下`。
- 已拍后显示缩略图和 `提交给家长`。

### 5.4 地点提醒

屏幕重点：

- 地点标签，不显示地图。
- `到公园后开始`。
- 主按钮：`我到了`。
- 无定位权限时仍可手动提交。

## 6. 家长端联动

家长端需要新增“手表验证方式”配置：

| 配置项 | 说明 |
| --- | --- |
| 不验证 | 孩子手动提交 |
| 步数验证 | 达标后自动提交 |
| 运动时长验证 | 统计活跃时间 |
| 动作估算 | 用于跳绳等，标注置信度 |
| 拍照证明 | 需要家长审核照片 |
| 地点提醒 | 只做提醒或地点标签命中 |

家长端审核卡片建议显示：

```text
跳绳 10 分钟
孩子已提交完成
手表辅助记录：估计 96 次，置信度中
照片：无
地点：未使用
[通过并发 3 星] [退回补充]
```

## 7. 合规与审核策略

- 传感器、相机、定位都必须按任务场景申请，不做一启动就全量索权。
- 拒绝权限后，基础任务查看和手动提交仍可使用。
- 定位不得用于广告、商业推荐或无关分析。
- 照片不得公开展示，默认只给监护人审核。
- 原始传感器数据不上传，只上传统计结果。
- 所有权限用途必须写入儿童隐私政策。
- 运动统计只能作为家庭任务辅助，不可包装成医疗、健康诊断或体能评估。

## 8. 分阶段落地

### Phase 1：明确可做

- 步数任务。
- 本地运动会话。
- 任务提醒通知。
- 家长审核卡片展示“手表辅助记录”。

### Phase 2：真机验证后做

- 跳绳/摆臂估算。
- 拍照证明任务。
- 翻盖继续任务。
- 小天才家长 APP 服务号报告。

### Phase 3：平台确认后做

- 地点标签命中。
- 到达/离开提醒。
- 位置辅助审核。
- 更深的小天才账号与家长端联动。

## 9. 当前实现边界

本轮先落地“展示层 + 领域模型”，暂不接真实小天才 SDK：

- 已实现：任务卡、运动进度、家长审核摘要、权限降级文案。
- 已实现：计步、跳绳、拍照、地点、愿望、审核、权限兜底的页面样式。
- 未实现：真实陀螺仪/加速度计采样。
- 未实现：真实相机拍摄和图片上传。
- 未实现：真实定位围栏和到达判断。
- 未实现：小天才账号、家长端、审核接口联调。

下一步接入时，应先让真机 SDK 写入统一的 `WatchActivitySnapshot` / `WatchProofSnapshot` 结构，再复用当前页面和家长审核摘要，避免每种传感器各写一套业务判断。
